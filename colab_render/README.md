# Аудіоп'єса на Colab або Kaggle

Рендер книги за ролями на GPU Colab (підписка Google AI Pro) з вашого сервера. Браузер для цього не потрібен.

- `render_chapter.py` працює на VM Colab: озвучує главу через OmniVoice або VoxCPM2.
- `orchestrate.py` працює на сервері (тільки стандартна бібліотека Python): готує задачу, керує `colab`, збирає главу й доріжки за голосами, стежить, щоб сесії не лишалися увімкненими.
- `hermes/audiobook-colab/SKILL.md` — навичка для Hermes Agent: книга з Telegram → сценарій → рендер → mp3 назад.

## Чому голос більше не «пливе»

У старому `audio_drama_bot.py` голос змінювався з кількох причин. Тут кожну з них закрито:

| Було | Стало |
|---|---|
| Без еталона репліка йшла у VoiceDesign, і щоразу виходив новий голос (Диктор так звучав завжди) | Еталон wav + транскрипт обов'язкові для кожного голосу. Без них рендер не запуститься |
| Qwen3-TTS не підтримує українську | OmniVoice (за замовчуванням) і VoxCPM2 підтримують українську та російську |
| Seed в авторегресійній моделі не тримав тембр | Голос задає один раз побудований clone-prompt. Seed фіксований на голос, OmniVoice за замовчуванням обирає токени детерміновано |
| Темп змінювався ресемплінгом, тож зсувалась і висота | Темп передається в саму модель |

## Встановлення на сервері (Linux)

```bash
uv tool install google-colab-cli     # або: pip install google-colab-cli
colab usage                          # перший запуск дасть посилання: увійдіть в акаунт з AI Pro і вставте код у термінал
git clone https://github.com/vadymvertyan-stack/audiobook ~/audiobook
```

CLI працює тільки на Linux/macOS, на Windows його немає. Окремо треба поставити тільки `ffmpeg`, і то за бажанням: з ним глава також зберігається в mp3.

## Голоси

`voices.json`, шляхи відносно цього файлу:

```json
{
  "Диктор": {"ref_audio": "narrator.wav", "ref_text": "Точний текст, який звучить у записі.", "seed": 101},
  "Марта":  {"ref_audio": "marta.wav",    "ref_text": "...", "seed": 202, "speed": 1.0}
}
```

Старий `voice_library.json` з Google Drive теж читається напряму (`--voices /шлях/до/voice_library.json`).

Вимоги до еталона: 16-bit PCM wav, **3–10 секунд** (ваші старі еталони на 15–20 с варто обрізати разом із текстом), сухий запис без ехо, мова та сама, що й у книзі. Транскрипт має збігатися з записом слово в слово. Якщо в тексті є слово, якого немає в записі (наприклад, запис обрізано посеред фрази), OmniVoice вимовлятиме його на початку кожної репліки. Тому перед рендером OmniVoice розпізнає еталон через Whisper і зупиняється, якщо перше чи останнє слово не збігається з текстом.

## Розмітка книги

```
# Розділ 1. Ліс
[voice:Диктор] Була темна ніч.
[voice:Марта] — Ти чуєш? Хтось іде.
[pause 1.5s]
[voice:Диктор] Вона прислухалася.

[voice:Олег] — Це лише вітер.
```

Старі файли з `Audio_Ready_Qwen` (`ID / Text / System_Prompt`) перетворюються на цю розмітку однією командою. Кожна сцена стає окремою главою, усі репліки йдуть голосу `--voice`:

```bash
python3 orchestrate.py import-qwen ~/audiobook-data/books/echo/src/Audio_Ready_Qwen --out script.txt --voice Диктор
```

`System_Prompt` при цьому перетворюється на теги `[speed 0.9]` (slow / fast / urgent) і `[volume 0.55]` (whisper / quiet). Емоцію OmniVoice бере лише з еталона, тож текстові вказівки змінюють тільки темп і гучність.

`#` починає главу, `[voice:Ім'я]` перемикає голос до наступного тегу, порожній рядок дає довшу паузу абзацу. Довгі абзаци автоматично розбиваються за реченнями. `прив+ет` позначає наголос (`+` перед наголошеною голосною). `[speed 1.1]` і `[volume 0.6]` змінюють темп і гучність лише того рядка, де стоять.

Паузи між репліками залежать від розділових знаків: 0,22 с, якщо наступний рядок продовжує речення (після коми, з малої літери або з дієприслівника на кшталт «Превратившись»); 0,55 с після крапки; 0,65 с після `?` і `!`; 0,8 с після `…`; 1 с перед прямою мовою і після неї (рядок починається з `—` чи `«` або містить «— прохрипел», «— сказал» тощо); 1,2 с між абзацами. Перевірити паузи без GPU: `plan --gaps`. `[pause 2s]` задає паузу явно.

## Команди

```bash
cd ~/audiobook/colab_render

# Перевірка без GPU: глави, голоси, оцінка тривалості
python3 orchestrate.py plan book.txt --voices voices.json

# Баланс CU
python3 orchestrate.py usage

# Рендер (одна сесія на всю книгу, модель вантажиться один раз)
python3 orchestrate.py render book.txt --voices voices.json --out out/ \
    --engine omnivoice --language uk --gpu L4

# Тільки перша глава, для тесту
python3 orchestrate.py render book.txt --voices voices.json --out out/ --chapters 1

# Сторож: знайти й зупинити забуті сесії (для cron кожні 15 хв)
python3 orchestrate.py watchdog --stop
```

Результат для кожної глави (`out/01_Розділ_1_Ліс/`):
- `chapter.wav` / `chapter.mp3` — готова глава;
- `stems/<голос>.wav` — окрема доріжка кожного голосу на всю довжину глави, щоб накладати фон;
- `lines/*.wav` — кожна репліка окремо;
- `manifest.json` — текст, час початку, seed і паузи для кожної репліки.

Повторний запуск тієї ж команди пропускає вже готові глави, тож після збою просто запустіть її знову. Сесія Colab зупиняється наприкінці завжди, навіть після помилки. Залишити її увімкненою можна тільки явним `--keep`.

## Kaggle (поки немає CU на Colab)

Той самий рендер, тільки як фоновий запуск приватного ноутбука Kaggle через офіційний `kaggle` CLI. Безкоштовно дається близько 30 GPU-годин на тиждень, один запуск триває до 12 годин.

Один раз на сервері:
1. Акаунт Kaggle має бути підтверджений номером телефону, інакше GPU та інтернет у ноутбуках недоступні.
2. `uv tool install kaggle` (або `pip install kaggle`).
3. Під vadym: `kaggle auth login --no-launch-browser`. Відкрийте посилання, яке виведе команда, і підтвердіть вхід. Перевірка: `kaggle config view` має показати ваш username.

Рендер:
```bash
python3 orchestrate.py render book.txt --voices voices.json --out out/ --backend kaggle --language uk
```

Як це працює: усі глави завантажуються як приватний датасет `audiobook-jobs`, потім запускається приватний ноутбук `audiobook-render` на T4 і рендерить їх усі за один запуск, тож модель вантажиться один раз. Сервер раз на хвилину перевіряє статус і після завершення забирає результат. Живої сесії тут немає, тож зупиняти нічого не треба. Якщо одна глава впала, решта зберігаються, а повторний запуск рендерить тільки відсутні. Хід рендеру видно на https://www.kaggle.com/code/<ваш-логін>/audiobook-render.

GPU P100 не підходить: сучасний PyTorch його вже не підтримує. Тому за замовчуванням стоїть `--kaggle-accelerator NvidiaTeslaT4`.

## Наголоси

- `--stress strip` (за замовчуванням): знаки `+` прибираються.
- `--stress acute`: `+е` перетворюється на `е́` (U+0301). OmniVoice це іноді враховує, але ненадійно, тож перевірте на своїх словах.
- `--stress keep`: `+` лишається (для моделей, навчених на такій нотації).
- `--lexicon words.json`: `{"слово": "написання для вимови"}` — найнадійніший спосіб виправити конкретне слово.

## Hermes

Скопіюйте `hermes/audiobook-colab/` у `~/.hermes/skills/` і додайте в Hermes cron:
`python3 ~/audiobook/colab_render/orchestrate.py watchdog --stop` кожні 15 хвилин.

## Тести

Без GPU і без Google, з фейковим `colab` і тестовим рушієм:

```bash
pip install numpy

```

## Що ще не перевірено

На справжніх Colab і Kaggle цей код ще не запускався: для цього потрібні ваші акаунти. Перший прогін глави покаже швидкість і витрату CU. На ньому ж перевіримо, що `pip install omnivoice` стає на образ Colab без конфліктів.
